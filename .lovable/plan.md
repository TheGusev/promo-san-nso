## Принято: Telegram исключаем

Тогда остаются три реальных вектора. Идём по ним по очереди — от самого вероятного к самому экзотическому.

### Вектор A. Утечка из админ-панели `/admin/leads` (вероятность ~60%)
Кто-то знает пароль (бывший сотрудник, подсмотрели, слабый пароль, переиспользованный с другого сайта).

### Вектор B. Прямое чтение БД через дыру в RLS (вероятность ~30%)
Если на таблице `leads` есть политика `SELECT` для роли `anon` — любой человек со страницы сайта через DevTools может выгружать заявки запросом к REST API. Это нужно проверить **первым делом**, потому что лечится за 1 минуту.

### Вектор C. Перехват у клиента (вероятность ~10%)
Контекстная реклама конкурента по вашему бренду + подменённый номер, либо колл-трекинг чужой. Это не наша проблема — это маркетинг.

## План действий

### Шаг 1. Аудит RLS на таблице `leads` (делаю первым, сразу)
- Прочитать политики `public.leads` через `supabase--read_query`.
- Если есть `SELECT TO anon` или `SELECT TO public` — это и есть дыра. Конкурент открывает ваш сайт, в консоли делает `fetch('/rest/v1/leads?select=*')` с публичным ключом и видит всё.
- Если нашли — миграцией закрыть: оставить `SELECT` только для `service_role` и для админа через `has_role(auth.uid(), 'admin')`.
- Заодно проверить `traffic_events` — там UTM, телефонов нет, но всё равно должно быть закрыто.

### Шаг 2. Логи доступа к админке
- Запрос к `traffic_events`: все `page_url ILIKE '%/admin%'` за 14 дней, сгруппировать по IP.
- Если виден чужой IP, который заходил на `/admin/leads` — это и есть утечка. Меняем пароль, добавляем 2FA-подобную защиту (одноразовый код в Telegram владельцу при логине).
- Сейчас в `src/pages/admin/Login.tsx` уже есть блокировка после 5 неудач. Усилим: при успешном входе с нового IP — слать уведомление в Telegram владельцу.

### Шаг 3. Усилить пароль и сессии админа
- Принудительно сбросить текущую сессию админа (инвалидация JWT).
- Попросить вас задать **новый пароль** 16+ символов (сгенерирую и покажу в чате один раз).
- Срок жизни сессии — 12 часов вместо «вечно».

### Шаг 4. Дополнительные замки на edge-функции
- В `handle-lead` принимать запросы только с `Origin` ∈ {`https://гордэз.рф`, `https://xn--c1acj0ak3f.xn--p1ai`, `https://*.lovable.app`}. Чужие → 403. Это не остановит атакующего с браузером, но отсечёт автоматизированные скрипты.
- Rate-limit на `handle-lead` поднять до 3 заявок/мин/IP.

### Шаг 5. (По желанию) Канарейка — ловушка на конкурента
- Завести тестовую заявку с уникальным именем «Иван Контрольный, +7 999 000-XX-XX» (номер на вашу вторую SIM-карту).
- Если по ней позвонят — значит утечка точно работает. Время звонка покажет окно, в котором атакующий читает данные → сопоставляем с логами доступа → находим IP/аккаунт.
